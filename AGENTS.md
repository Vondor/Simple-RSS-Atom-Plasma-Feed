# AGENTS.md — Simple RSS / Atom Plasma Feed

Rules for any AI agent that changes this repository. The team-wide working rules (roles, pull requests, CI failures, self-merge, notifications, sample data) are in the private repository `Vondor/Agent-Teams`: start at its `AGENTS.md`. This file wins on anything about this product's code; its boundaries and human gates are never changed from Agent-Teams.

## What it is

A KDE Plasma 6 widget (plasmoid, id `org.kde.plasma.rssreader`) that merges any number of RSS and Atom feeds into one list, newest first. Plain QML in a KPackage, no compiled code. Distributed as a `.plasmoid` file on the KDE Store (https://store.kde.org/p/2363221/), outside KDE's own infrastructure and translation pipeline.

```
metadata.json                 package id, name, version, license, translated name/description
contents/config/main.xml      settings schema (KConfigXT)
contents/config/config.qml    settings pages
contents/ui/main.qml          widget, feed loading and parsing, list
contents/ui/configGeneral.qml settings page
contents/icons/rssreader.svg  widget icon ("Icon": "rssreader")
contents/screenshot.png       widget-browser picture, also drawn by the compact view
contents/locale/              compiled .mo files, generated by translate/build.sh
translate/                    .po sources, template.pot, merge.sh, build.sh
ci/                           checks and distro tests used by CI, runnable locally
```

## Boundaries

- **Works out of the box on a stock Plasma 6 desktop** (bare Kubuntu, Debian, Fedora). Only modules that ship with every Plasma 6 install (QtQuick, QtCore, Kirigami, Plasma components, plasmoid). No compiled plugins, no extra runtime packages, no install scripts or manual setup steps for users. Everything must travel inside the `.plasmoid`.
- **Per-instance settings stay per instance.** Settings use `QtCore` `Settings` with `category: "SimpleRSSFeed_" + Plasmoid.id`, because `Plasmoid.configuration` mixes values between instances. Do not move them back. `Plasmoid` is not available in config pages.
- **Network access only to the feed URLs the user configured.** No telemetry, no other hosts.
- **No personal data.** The widget stores only feed URLs, filters and display options.
- **Translations are self-contained.** Never edit `.mo` files or the translated keys in `metadata.json` by hand: change `.po` files, then run `sh translate/build.sh`; after changing any `i18n()` string run `sh translate/merge.sh` first. CI fails if they are out of date. Shipped: `de`, `en`, plus `tlh` and `qya` as easter eggs.
- UI text in English, German kept in step.
- Debug code is clearly marked (`// === DEBUG (testing) ===`) and removed before merge.

## Human gates

These wait for the maintainer (Vondor). Tick every gate a pull request touches, so the record shows it. Agents do not merge pull requests in this repository unless the maintainer says so for that pull request or records a general permission here.

- License (`LICENSE`, `metadata.json` "License")
- Package id (`metadata.json` "Id"); changing it breaks every existing install
- Version number and releases (`metadata.json` "Version", `v*` tags, publishing to the KDE Store)
- A new dependency or a raised minimum Plasma version (`X-Plasma-API-Minimum-Version`)
- Author, publisher or branding (`metadata.json` "Authors", logos)
- This file's boundaries or human gates
- CI, workflow or branch-protection changes

## Checks

CI (`.github/workflows/ci.yml`) builds the `.plasmoid` and installs it on fresh Kubuntu 26.04, Debian 13 and Fedora 43/44 containers with only the stock Plasma packages; Ubuntu devel and Fedora Rawhide run too but may fail. `main` is protected: these checks must be green before a pull request can merge. Run the fast part locally:

```
python3 ci/check-package.py      # metadata, layout, icon
sh ci/check-translations.sh      # .pot/.mo/metadata.json up to date (needs gettext)
sh ci/build-plasmoid.sh          # writes dist/rssreader-<version>.plasmoid
/usr/lib/qt6/bin/qmllint contents/ui/*.qml   # expect some Kirigami stub noise
```

The distro tests need the distributions' mirrors and only run on GitHub Actions. CI cannot judge how the widget looks or behaves. The maintainer checks that on their desktop; hand them one command, for example

```
kpackagetool6 -t Plasma/Applet -u . || kpackagetool6 -t Plasma/Applet -i .
```

then "restart Plasma (`plasmashell --replace &`) and you should see …". Before touching their local checkout, follow Agent-Teams `general/rules/local-checkouts.md`.

## Pull requests

- One purpose per pull request, opened from a `claude/…` branch; never push to `main` directly. The body follows `.github/pull_request_template.md` and keeps its full human-gate list.
- Commit messages say what changed and why, for an agent with no memory of the session.

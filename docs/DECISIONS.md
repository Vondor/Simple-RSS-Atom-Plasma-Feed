| D-016 | 2026-11-18 | Feed text is decoded like this (`feedparser.js`): entities in one pass (named and numeric together, `String.fromCodePoint`, so emoji survive and `&amp;#60;` stays the text `&#60;`); an unknown name or invalid number is left as written. A CDATA section is cut out before tags are removed and its content is treated as HTML (tags removed, entities decoded once); only `<` followed by a letter or `/` counts as a tag, so `3 < 5` is text. Whitespace in titles collapses to one space. Atom `href` values are decoded. The source name is the first `<title>` before the first item, outside `<image>`. An RSS item without `<link>` takes its `<guid>` when it is a permalink and an `http(s)` address. Decided by the AI (Claude Code, Opus 5.5). | Issue #30: wrong links and garbled titles. CDATA as HTML rather than literal XML text because feeds put markup there in practice. | #30, this PR |
| D-017 | 2026-11-18 | Feed dates are read like this (`feedparser.js` `parseDate`): first as an RFC 822 date as RSS uses it (weekday and seconds optional, two-digit years, zone as an offset or a name such as `UT`, `GMT`, `PDT` or `CET`, a trailing comment such as `(PDT)` ignored; a missing or unknown zone name counts as UTC), otherwise with the engine's own `Date` (ISO 8601). The date taken is the first of Atom `<published>`, RSS 2.0 `<pubDate>`, RSS 1.0 `<dc:date>`, then Atom `<updated>`. Dates are shown in the user's short date-time format from Plasma's region settings (`Date.toLocaleString(Qt.locale(), Locale.ShortFormat)`), "Last Updated" in the short time format; the `Intl` time-zone code is gone, as QML's engine has no `Intl`. German users see the same `17.11.26 10:00` as before. Decided by the AI (Claude Code, Opus 5.5). | Issue #31: common RSS dates failed to parse and sank to the bottom, RSS 1.0 feeds were undated, Atom order depended on tag order, and the date was always written in the German order. UTC for an unknown zone keeps the article within hours of its real place instead of at the bottom. | #31, this PR |

| D-019 | 2026-11-18 | A failed refresh never empties the list (issue #32): each feed's articles from its last good refresh are kept in memory only (no cache on disk, so the non-goals hold) and shown again when that feed fails; a removed feed's articles are forgotten (`feedparser.js` `combineResults`).
